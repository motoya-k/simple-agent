# simple-agent

Hermes Agent の設計を、依存パッケージなしの Python 約 1,700 行に書き直した最小構成のエージェント。

本家（`cli.py` だけで 70 万字、ソース 10MB 弱）から機能を削るのではなく、**設計思想だけを持ち出してゼロから書いた** ものです。エージェントループ・ツール・記憶・スキル学習・会話検索が実際に動きます。ゲートウェイ・委譲・TUI・マルチプロバイダは、実装せずに接続点（インターフェース）だけを置いてあります。何をどこまで持ち込んだかは [DESIGN.md](DESIGN.md) に書きました。

このリポジトリの読み方——**1〜3 章は最初に通して読む**（動かすまで）。4 章以降は必要なときに引いてください。

---

## 1. 動かす

```bash
cp .env.example .env        # ANTHROPIC_API_KEY を書く
python -m simple_agent      # 対話モード
python -m simple_agent "このリポジトリの構成を教えて"   # 一発実行
```

Python 3.10 以上があれば、`pip install` は要りません。標準ライブラリだけで動きます。

状態は `~/.simple-agent/` の下に置かれます。

```
~/.simple-agent/
├── memories/MEMORY.md   環境と仕事についての記憶（上限 2,200 字）
├── memories/USER.md     あなたについての記憶（上限 1,375 字）
├── skills/<名前>/SKILL.md   エージェントが自分で書いた手順書
├── state.db             全会話の SQLite（全文検索インデックス付き）
└── shell/               ターミナルセッションのスナップショット
```

## 2. 対話モードのコマンド

| 入力 | 何が起きるか |
| --- | --- |
| `/memory` | いまシステムプロンプトに載っている記憶をそのまま表示 |
| `/skills` | スキル一覧を状態（active / stale / archived）と使用回数つきで表示 |
| `/search <語>` | 過去の全会話を全文検索。日本語もそのまま引ける |
| `/sessions` | 直近のセッション一覧 |
| `/cost` | このセッションのトークン消費と上限 |
| `/exit` | 終了（Ctrl-D も同じ） |

それ以外の入力はエージェントに渡ります。

## 3. エージェントが持っている道具

| ツール | できること | 並列実行 |
| --- | --- | --- |
| `terminal` | bash を実行。**cwd・環境変数・シェル関数が呼び出しをまたいで残る** | しない |
| `read_file` | 行番号つきでファイルを読む。ディレクトリなら一覧 | する |
| `write_file` / `edit_file` | 書き込みと文字列置換 | しない |
| `memory` | MEMORY.md / USER.md の読み書き | しない |
| `skill_view` / `skill_manage` | 手順書を読む・書く・直す | 読みのみ |
| `session_search` | 過去の会話を全文検索 | する |

読むだけのツールは最大 8 並列で走り、状態を変えるツールはモデルが指示した順に 1 つずつ実行されます。同じファイルへの二重書き込みが競合しないため、そして順序そのものにモデルの意図が乗っていることがあるためです。

## 4. 使うほど賢くなる仕組み

ターンが終わるたびに、**別スレッドで安いモデルのレビュー担当が起動します**（`simple_agent/review.py`）。ユーザーは待ちません。レビュー担当が持てる道具は記憶とスキルだけで、コマンドも実行できないし、ユーザーに話しかけることもできません。

見ているのは 2 点です。ひとつは「ユーザーは自分のことや、こう働いてほしいという期待を明かしたか」。もうひとつは「次のセッションが最初から知っておくべきことが起きたか」。後者のプロンプトはわざと押しが強く書いてあります。何もしないパスを安全な既定にすると、学習ループは永久に何も学ばないからです。

記憶には書き込み上限があります（MEMORY.md が 2,200 字、USER.md が 1,375 字）。増やせない予算があるからこそ、本当に効くことだけが残ります。

そして書き込んだ記憶は**次のセッションから効きます**。今のセッションのシステムプロンプトは開始時に凍結され、途中で書き換わりません。理由は 5 章に書きました。

## 5. 知っておくと動きが読める設計

**プロンプトの前半は神聖**。システムプロンプトは `Agent.__init__` で 1 度だけ組み立て、セッション中は変わりません。記憶の更新はディスクにだけ書きます。途中で前半を書き換えると、プロバイダのプロンプトキャッシュが毎ターン無効になり、ユーザーの請求額が静かに数倍になります。

**核は細く、能力は端に**。`agent.py` と `loop.py` はプロバイダの SDK も、ツールの中身も、表示の仕方も知りません。ツールを足すのは `tools/` にファイルを 1 つ増やす作業で、ループには触れません。

詳しい理由と、実装しなかった 4 つの機能の設計は [DESIGN.md](DESIGN.md) にあります。

## 6. ファイルの地図

| 知りたいこと | 見るファイル |
| --- | --- |
| ループ本体（20 行で終わる） | `simple_agent/loop.py` |
| エージェントの核クラス | `simple_agent/agent.py` |
| 記憶の凍結スナップショット | `simple_agent/memory.py` |
| スキルの生成・熟成（active → stale → archived） | `simple_agent/skills.py` |
| 学習ループのプロンプト実物 | `simple_agent/review.py` |
| SQLite と FTS5（日本語検索は trigram） | `simple_agent/state.py` |
| LLM との通信（ここだけ） | `simple_agent/providers/anthropic.py` |
| 実装していない機能の接続点 | `simple_agent/seams.py` |

## 7. テスト

```bash
python -m venv .venv && .venv/bin/pip install pytest
.venv/bin/python -m pytest tests -q
```

ネットワークにはつながりません。LLM の代わりに、あらかじめ用意した応答を順に返す `ScriptedProvider` を差し込んでいます。プロバイダが 1 つのインターフェースに閉じているからできることです。

## 8. 用語

- **ターン** — ユーザーの 1 発言に対し、答えが出るまでのモデル呼び出しとツール実行のひとまとまり。
- **凍結スナップショット** — セッション開始時に読み込み、そのセッション中は変えない記憶のコピー。
- **narrow waist（細い腰）** — 中心を小さく保ち、機能は周縁のプラグインとして足す構造。砂時計のくびれの比喩。
- **seam（接続点）** — 実装はないが、実装するならここに繋がるという境界。`seams.py` がそれです。
